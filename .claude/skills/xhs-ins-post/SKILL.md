# 小红书官网复盘帖 · 全自动流水线

用户只做最后一个决定：在浏览器里看完点「发布」。中间所有步骤你自己完成，**不要中途停下来问用户**（除非下面明确写了要问）。全程用中文和用户说话，用户不懂技术，回复要短。

## 0. 开始前
- 网址：用户给的。品牌名 `<brand>` 取域名主体，小写英文（如 wwake.com → `wwake`）。
- 账号：看 `accounts/` 下有哪些文件夹（`.gitkeep` 不算）。只有一个就直接用；多个时问用户用哪个；一个都没有，让用户先双击 `2-登录账号.command` 扫码。
- 口吻：用户说"跑帖子 <网址>"默认是**我们做的项目**（第一人称"我们"）；用户说"拆解 <网址>"时用第三人称分析别人的网站，不能写成我们做的。

## 1. 截图
```bash
python3 -m xhs.shoot <网址> --name <brand>
```
产出 `materials/<brand>/shots/*.png` 和 `materials/<brand>/pages.json`（每页的标题、小标题、段落、价格）。

截完**逐张看截图**（用 Read 打开图片）：
- 有弹窗、cookie 条、空白、加载失败的页面，从 `pages.json` 的 `pages` 里删掉那一项。
- 截图太少（少于 3 页）时，可以从首页导航里再挑页面，用 `--pages 8` 重跑。

## 2. 做图
```bash
python3 -m xhs.mockup <brand>
```
输出 `posts/<brand>/1.png 2.png …`，3:4 白底，左电脑框、右手机框。第 1 张（首页）是封面。打开封面看一眼，确认没有明显问题。

## 3. 写文案 → `posts/<brand>/post.json`
```json
{"account": "<账号>", "title": "…", "body": "…", "tags": ["…"]}
```

### 素材
只用截图里看得到的、`pages.json` 里有的信息：品牌、城市、价格、品类数量、工艺、材质、产地、页面版式。**不许编数字、不许编客户原话、不许编不存在的功能。**

### 标题（≤20 字，含标点和英文字母）
- **必须同时出现品牌名和行业词**（如「WWAKE」+「珠宝」）。
- 带一个读者能拿走的价值点：几个细节 / 几招 / 价格带。
- 参考：`WWAKE珠宝官网复盘：7个高客单价细节`、`珠宝官网怎么做？WWAKE的7个细节`、`980美金珍珠项链，WWAKE官网复盘`。
- 写进 post.json 的用最好的一个；另外 2 个备选在最后告诉用户（用户可以在发布页直接改）。

### 正文结构（严格按这个格式）
```
开头 1–2 句：品牌是谁、在哪、卖什么价位（我们口吻：「最近做完了…的官网」）。

复盘出 N 个做法，做<相关行业1>、<相关行业2>这类<客单价/类型>官网的朋友可以直接用👇

<emoji> 01 <小标题：一句可执行的做法>
做法：<我们具体怎么做的，带截图里的真实细节>
原因：<为什么有效，从用户心理/转化角度说>

<emoji> 02 …（共 5–8 条）

📌 一句话总结
<一句朴素、有洞察的话>
```
- 每条小标题前一个贴合内容的 emoji（📸 🔢 🖼️ 🧵 📍 🤝 🏛️ 这类），编号两位数。
- 「做法」「原因」各一行，短句。
- 全文 600–850 字，加上话题后不超过 1000 字。

### 去 AI 味（硬性）
- 像设计师跟同行聊天，说人话。
- 禁用：「赋能」「打磨」「致力于」「匠心」（引用对比时除外）、「这不是X，而是Y」句式、「X＝Y」公式、破折号排比、三连形容词金句、「让我们」「值得一提的是」「总而言之」。
- **结尾不要互动句**：不写「评论区聊聊」「你们觉得呢」「先收藏」「关注我」之类。正文到「📌 一句话总结」那句就结束。

### 利他
- 每条都要让读者能用到自己的项目上：说清楚怎么做 + 为什么。
- 开头点明适用于哪些行业的官网。

### 按行业换观察角度（不要把 A 行业的说法套到 B 行业）
| 行业 | 重点看什么 |
|---|---|
| 珠宝/奢品 | 佩戴特写 vs 静物、工艺和材质怎么写、产地透明、预约/门店页 |
| 户外/装备 | 参数怎么展示、视频首屏、信号色只用于按钮、产品卡结构一致 |
| SaaS/科技 | 真实界面截图、可交互演示、少营销词、单一品牌色 |
| 餐饮/食品 | 食材特写、产地、时令、纸感/手写元素 |
| 美妆/护肤 | 质地微距、成分和浓度、临床数据卡、肤色调 |
| 家居/空间 | 光线和动线、材质近景、平面图、留白 |
| 教育 | 学员作品、成果对比、课程结构可视化 |
| 其他 | 先想：这个行业最常见的 2 种俗套页面是什么？用户最不信任什么？这个网站怎么正面回应？ |

### 话题 tags（5–6 个）
`网页设计`、`品牌设计`、`UI设计`、`<行业词>`、`设计干货`、`官网设计`，行业词按实际替换。

写完自查：标题字数 ≤20 且含品牌+行业；没有禁用词；没有互动结尾；所有数字都能在截图或 pages.json 里找到。

## 4. 自动填写，等用户点发布
```bash
python3 -m xhs.publish post posts/<brand> --account <账号>
```
**用后台方式运行**（这个命令会一直等到用户在浏览器里发完或关掉窗口才结束）。它会打开小红书、上传图片、填好标题正文话题，然后停在发布页。

然后告诉用户（只说这些）：
- 浏览器已经填好了，检查后点「发布」；不想发就关掉浏览器窗口。
- 标题备选 2 个（想换可以在发布页直接改）。

命令结束后看输出：
- `已发布` → 告诉用户发好了。
- 报错 → 看 `posts/<brand>/error.png` 和报错信息，修 `xhs/publish.py` 后重试一次；还不行就告诉用户正文已在剪贴板，可以在打开的浏览器里手动粘贴。

## 绝不做
- 不替用户点「发布」（除非用户明确说"直接发"）。
- 不把 `accounts/`、`materials/`、`posts/` 里的东西提交或上传到 GitHub。
